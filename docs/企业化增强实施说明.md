# 企业化增强实施说明

## 目标

在现有双节点实验集群上补齐几项最能体现工程能力的内容：**可配置发布、健康检查、滚动更新、镜像流水线、告警规则和故障演练**。

当前 Chart 使用 `nginx:latest` 进行本地验证，因此保留 `allowPrivilegeEscalation: false`，暂不对容器能力做 `drop: ALL`。官方 Nginx 启动脚本需要调整缓存目录权限；如果后续切换到专门的 unprivileged Nginx 镜像，再单独收紧用户和 capabilities。

这仍然是本地实验项目，不把它描述成生产级高可用平台。企业化增强的重点是让部署过程可重复、发布过程可追踪、故障现象可观测。

## 新增内容

```text
Dockerfile                         构建自定义 Nginx 镜像
site/index.html                    可验证镜像版本的页面
.github/workflows/build-image.yml  GitHub Actions 构建并推送到 GHCR
deploy/helm/nginx-demo/            Helm Chart，统一管理应用配置
monitoring/alerts/                 PrometheusRule 告警样例
docs/故障演练手册.md                可重复执行的故障演练
```

## 一、先检查 Helm Chart

在项目根目录执行：

```bash
helm lint deploy/helm/nginx-demo
helm template nginx-demo deploy/helm/nginx-demo --namespace demo
```

`helm lint` 检查 Chart 结构；`helm template` 只渲染 YAML，不会修改集群。

## 二、使用 Helm 部署增强版应用

为了不覆盖之前 `default` 命名空间中的实验资源，增强版使用独立的 `demo` 命名空间。

```bash
helm upgrade --install nginx-demo deploy/helm/nginx-demo \
  --namespace demo \
  --create-namespace
```

验证：

```bash
kubectl get deployment,pod,svc -n demo -o wide
kubectl rollout status deployment/nginx-demo-nginx-demo -n demo --timeout=120s
```

## 三、使用自定义镜像发布

GitHub Actions 成功运行后，镜像会推送到：

```text
ghcr.io/<GitHub用户名>/<仓库名>:latest
```

镜像仓库名称必须替换为自己的仓库地址：

```bash
helm upgrade nginx-demo deploy/helm/nginx-demo \
  --namespace demo \
  --set image.repository=ghcr.io/<GitHub用户名>/<仓库名> \
  --set image.tag=latest
```

更推荐使用 Git commit SHA 作为 tag，避免 `latest` 被覆盖后难以回滚。GitHub Actions 已同时生成 SHA tag。

## 四、验证健康检查和滚动更新

```bash
kubectl describe deployment nginx-demo-nginx-demo -n demo
kubectl get pods -n demo -w
```

观察 `Readiness probe`、`Liveness probe` 和新旧 ReplicaSet 的切换。

修改 `site/index.html` 后重新提交到 GitHub，Actions 构建新镜像，再执行：

```bash
helm upgrade nginx-demo deploy/helm/nginx-demo \
  --namespace demo \
  --set image.repository=ghcr.io/<GitHub用户名>/<仓库名> \
  --set image.tag=<commit-sha>
kubectl rollout status deployment/nginx-demo-nginx-demo -n demo
```

## 五、回滚

```bash
helm history nginx-demo -n demo
helm rollback nginx-demo <revision> -n demo
kubectl rollout status deployment/nginx-demo-nginx-demo -n demo
```

## 六、告警与故障演练

告警规则文件位于 `monitoring/alerts/`。先阅读其中的 CRD 前置条件，再决定是否应用。

故障演练建议按 [故障演练手册](故障演练手册.md) 执行，并记录：故障注入时间、观察到的指标、定位命令、恢复时间和最终结论。

## 项目边界

- 单个 Control Plane，不宣称控制平面高可用；
- 本地环境关闭了部分持久化能力，不宣称数据可靠性；
- Metrics Server 的 `--kubelet-insecure-tls` 仅用于实验；
- GitHub Actions 默认只负责构建和推送镜像，不把本地 kubeconfig 放入 GitHub。
