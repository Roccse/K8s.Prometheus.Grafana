# 项目摘要（简历与面试用）

## 项目名称

Kubernetes 双节点云原生监控与故障排查平台

## 一句话介绍

在本地虚拟机上搭建 kubeadm 双节点 Kubernetes 集群，部署 Nginx 业务工作负载，通过 NodePort 提供访问入口，并使用 Prometheus、Grafana 和 Kubernetes exporters 构建可观测性和故障验证链路。

## 简历描述（可直接改写）

- 基于 kubeadm 搭建双节点 Kubernetes 集群，使用 Flannel 完成跨节点 Pod 网络配置，部署并验证 Nginx 工作负载。
- 使用 Deployment、Service、NodePort 实现应用发布和服务发现，完成副本扩容、跨节点调度及 Pod 删除后的自动自愈验证。
- 部署 Metrics Server、node-exporter、kube-state-metrics、Prometheus 和 Grafana，编写 PromQL 查询并创建节点与 Kubernetes 状态监控面板。
- 针对 Flannel CrashLoopBackOff、镜像拉取失败、CoreDNS 异常、PVC Pending、Metrics Server 证书错误和 NodePort/nftables 差异进行事件、日志、Endpoint 和节点网络排查。
- 在 Worker 无法访问外部镜像仓库时，使用 containerd 镜像导出、SSH 传输和离线导入恢复业务与系统组件。

## 面试讲解顺序

```text
为什么做 → 集群架构 → 应用发布 → 监控链路 → 真实故障 → 排查证据 → 修复与验证 → 后续改进
```

## 必须能够独立解释的概念

- Control Plane、Worker、kubelet、containerd、etcd；
- Pod、Deployment、ReplicaSet、Service、Endpoint、NodePort；
- CNI、Flannel、kube-proxy、iptables/nftables；
- Readiness、Liveness、CrashLoopBackOff、ImagePullBackOff；
- Metrics Server 与 Prometheus 的区别；
- Exporter、PromQL、Grafana Dashboard、Alertmanager；
- PVC、StorageClass，以及实验环境关闭持久化的原因。

## 项目边界

这是本地实验环境，不应描述为生产集群。当前监控使用了实验性配置，例如 Metrics Server 的 `--kubelet-insecure-tls` 和关闭 Prometheus 持久化。后续生产化方向是正确签发 kubelet 证书、配置 StorageClass/PV/PVC、固定镜像版本、接入 CI/CD 和完善告警。
