# Kubernetes 云原生实验集群完整部署过程

> 本文按本项目的实际实验顺序整理：**双节点 kubeadm 集群 → Flannel 网络 → Nginx 应用 → NodePort → Metrics Server → Prometheus → Grafana**。
>
> 节点 IP、用户名和镜像版本请按自己的环境替换。本文不包含密码、Token、kubeconfig 或镜像仓库凭据。

------

## 一、实验环境

| 角色 | 主机名 | IP | 说明 |
| --- | --- | --- | --- |
| Control Plane | `k8s-master` | `192.168.121.10` | 运行 API Server、Scheduler、Controller Manager 等控制组件 |
| Worker | `k8s-worker` | `192.168.121.11` | 运行业务 Pod 和节点组件 |

```text
Kubernetes：v1.30.14
容器运行时：containerd
CNI：Flannel
业务示例：nginx-demo
监控组件：Metrics Server、Prometheus、Grafana
```

## 二、两台节点的基础准备

以下步骤需要在 **Master 和 Worker 都执行**。

### 1. 固定主机名和静态 IP

```bash
hostnamectl
ip addr
ip route
```

确认两台机器的地址稳定后再初始化集群。Netplan 中应关闭 DHCP，并写入对应静态地址；具体问题和修复记录见 [静态 IP 故障](Kubernetes%20云原生实验集群排障记录.md#二静态-ip-被-dhcp-覆盖)。

### 2. 关闭 Swap

```bash
sudo swapoff -a
sudo sed -i.bak '/ swap / s/^/#/' /etc/fstab
free -h
```

**预期结果：** `Swap` 显示为 `0B`。

### 3. 加载内核模块并设置转发参数

```bash
sudo modprobe overlay
sudo modprobe br_netfilter

sudo tee /etc/modules-load.d/k8s.conf >/dev/null <<'EOF'
overlay
br_netfilter
EOF

sudo tee /etc/sysctl.d/k8s.conf >/dev/null <<'EOF'
net.bridge.bridge-nf-call-iptables = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward = 1
EOF

sudo sysctl --system
```

**作用：** 允许 Linux 正确转发 Pod 网络流量，并让 iptables/nftables 能处理桥接网络流量。

### 4. 安装并配置 containerd

```bash
sudo apt-get update
sudo apt-get install -y containerd

sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml

sudo systemctl enable --now containerd
sudo systemctl restart containerd
sudo systemctl status containerd --no-pager
```

**预期结果：** `Active: active (running)`。

### 5. 安装 kubeadm、kubelet、kubectl

```bash
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl gpg

sudo mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.30/deb/Release.key | \
  sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.30/deb/ /' | \
  sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl
sudo apt-mark hold kubelet kubeadm kubectl
```

```bash
kubeadm version
kubelet --version
kubectl version --client
```

## 三、初始化 Control Plane

以下步骤只在 **Master** 执行。

### 1. 初始化集群

```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.121.10 \
  --pod-network-cidr=10.244.0.0/16
```

`10.244.0.0/16` 是本实验使用 Flannel 时指定的 Pod 网段。

### 2. 配置 kubectl

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown "$(id -u):$(id -g)" $HOME/.kube/config

kubectl get nodes
```

此时 Master 可能暂时处于 `NotReady`，因为 CNI 网络插件尚未安装。

### 3. 保存 Worker 加入命令

```bash
kubeadm token create --print-join-command
```

输出是一条以 `kubeadm join` 开头的命令；复制到 Worker 使用。Token 过期时可再次生成，**不要把完整 join 命令提交到 GitHub**。

## 四、安装 Flannel 并加入 Worker

### 1. 安装 Flannel（Master）

```bash
kubectl apply -f https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml
kubectl get pods -n kube-flannel -o wide
```

### 2. 加入 Worker（Worker）

将上一节输出的命令粘贴到 Worker，例如：

```bash
sudo kubeadm join 192.168.121.10:6443 \
  --token <token> \
  --discovery-token-ca-cert-hash sha256:<hash>
```

### 3. 验证双节点（Master）

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
```

**预期结果：** 两个节点都为 `Ready`；Master 和 Worker 上各有一个 Flannel Pod，状态为 `1/1 Running`。

如果 Worker 上出现 `FailedCreatePodSandBox`、`/run/flannel/subnet.env` 缺失或镜像拉取失败，先按 [Flannel 与镜像拉取故障复盘](incidents/flannel-and-image-pull.md) 排查，不要盲目重建集群。

## 五、部署 Nginx 示例应用

以下步骤在 **Master** 执行。

### 1. 创建 Deployment 和 Service

```bash
kubectl apply -f k8s/app/nginx-demo-deployment.yaml
kubectl apply -f k8s/app/nginx-demo-service.yaml
```

### 2. 确认 Pod 与 Service

```bash
kubectl get deployment nginx-demo
kubectl get pods -l app=nginx-demo -o wide
kubectl get svc nginx-demo-svc
kubectl get endpoints nginx-demo-svc
```

**预期结果：** `nginx-demo` 有两个 `Running` 副本，Service 存在后端 Endpoint。

### 3. 验证 NodePort

本项目清单固定使用 NodePort `31258`。在 Master 或 Worker 执行：

```bash
curl -I http://127.0.0.1:31258
curl -I http://192.168.121.10:31258
curl -I http://192.168.121.11:31258
```

返回 `HTTP/1.1 200 OK` 即表示访问成功。

### 4. 验证扩容与自愈

```bash
kubectl scale deployment/nginx-demo --replicas=2
kubectl get pods -l app=nginx-demo -o wide

kubectl delete pod <任意一个nginx-demo-pod名称>
kubectl get pods -l app=nginx-demo -w
```

删除 Pod 后，Deployment 会自动补齐副本；Service 只负责把流量转给存活且 Ready 的 Pod。

NodePort 若出现连接被拒绝，参照 [NodePort 与 nftables 故障复盘](incidents/nodeport-nftables.md)。本实验的关键结论是：Master 使用 nftables 后端，不能只用 `iptables-save` 判断规则是否存在。

## 六、部署 Metrics Server

以下步骤在 **Master** 执行。

### 1. 安装组件

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl get pods -n kube-system -l k8s-app=metrics-server
```

### 2. 实验环境中的证书处理

本实验的 kubelet serving certificate 缺少节点 IP SAN，因此 Metrics Server 需要添加以下参数：

```text
--kubelet-insecure-tls
```

可通过编辑 Deployment 添加：

```bash
kubectl -n kube-system edit deployment metrics-server
```

**说明：** `--kubelet-insecure-tls` 会跳过 kubelet 证书校验，只适用于学习环境；生产应正确签发和轮换证书。

### 3. 验证

```bash
kubectl rollout status deployment/metrics-server -n kube-system --timeout=120s
kubectl top nodes
kubectl top pods -A
```

## 七、部署 Prometheus 与 Grafana

以下步骤在 **Master** 执行，前提是已安装 Helm：

```bash
helm version
```

### 1. 添加 Chart 仓库

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo add grafana https://grafana.github.io/helm-charts
helm repo update
```

### 2. 安装 Prometheus

实验集群没有 StorageClass，因此先关闭持久化，避免 PVC 长期处于 `Pending`：

```bash
helm upgrade --install prometheus prometheus-community/prometheus \
  --namespace monitoring \
  --create-namespace \
  --set server.persistentVolume.enabled=false \
  --set alertmanager.persistence.enabled=false
```

```bash
kubectl get pods -n monitoring
kubectl get svc -n monitoring
```

### 3. 安装 Grafana

```bash
helm upgrade --install grafana grafana/grafana \
  --namespace monitoring \
  --set persistence.enabled=false

kubectl get pods -n monitoring
```

### 4. 访问 Prometheus 与 Grafana

为避免暴露本地实验服务，使用端口转发：

```bash
kubectl -n monitoring port-forward service/prometheus-server 9090:80
```

另开一个终端：

```bash
kubectl -n monitoring port-forward service/grafana 3000:80
```

Grafana 数据源地址填写：

```text
http://prometheus-server.monitoring.svc.cluster.local
```

在 Prometheus Targets 页面确认目标为 `UP`，再导入或创建 Grafana Dashboard。

镜像、Helm 仓库或代理出现问题时，参照 [Metrics Server、Prometheus 与 Grafana 故障复盘](incidents/metrics-and-prometheus.md)。

## 八、最终验收清单

```bash
kubectl get nodes -o wide
kubectl get pods -A -o wide
kubectl get svc -A
kubectl top nodes
kubectl top pods -A
```

验收时至少确认：

- Master 与 Worker 均为 `Ready`；
- Flannel、CoreDNS、kube-proxy 均正常运行；
- `nginx-demo` 两个副本为 `Running`；
- NodePort 从两个节点均可访问；
- Metrics Server 能返回节点和 Pod 资源用量；
- Prometheus Targets 为 `UP`；
- Grafana 能查询 Prometheus 数据源。
