# 通用排障手册

## 1. 先确认资源状态

```bash
kubectl get nodes
kubectl get pods -A -o wide
kubectl get events -A --sort-by=.lastTimestamp
```

## 2. Pod 不正常

```bash
kubectl describe pod <pod-name> -n <namespace>
kubectl logs <pod-name> -n <namespace> --previous
```

优先阅读 `Events`，常见状态含义：

| 状态 | 重点方向 |
| --- | --- |
| `Pending` | 调度、资源、PVC、污点 |
| `ContainerCreating` | CNI、Volume、sandbox |
| `ImagePullBackOff` | 镜像名称、仓库网络、认证、containerd |
| `CrashLoopBackOff` | 容器日志、配置、依赖服务 |
| `NotReady` | Readiness probe、应用端口、依赖服务 |

## 3. Service 访问异常

```bash
kubectl get svc <service-name>
kubectl get endpoints <service-name>
kubectl get endpointslice -l kubernetes.io/service-name=<service-name>
kubectl get pods -l app=<label> -o wide
```

先用 Pod IP 或 `kubectl port-forward` 验证应用，再排查 NodePort、kube-proxy 和节点防火墙。

## 4. 节点和运行时

```bash
kubectl describe node <node-name>
sudo systemctl status kubelet containerd
sudo journalctl -u kubelet -n 100 --no-pager
sudo crictl images
sudo ctr -n k8s.io images list
```

## 5. 安全原则

不要直接执行 `kubeadm reset`、删除整个 CNI 或手工写入 kube-proxy 的 iptables 规则。先收集证据，确认影响范围，再进行最小变更。
