# Kubernetes 故障演练手册

> 每次演练先记录当前状态，结束后恢复资源并再次验收。不要在没有备份或确认的情况下删除系统命名空间资源。

## 一、Pod 自愈

```bash
kubectl get pods -n demo -l app.kubernetes.io/name=nginx-demo -o wide
kubectl delete pod -n demo <一个nginx-demo-pod>
kubectl get pods -n demo -l app.kubernetes.io/name=nginx-demo -w
```

**预期：** Deployment/ReplicaSet 创建新 Pod，副本数回到 `2`。

## 二、错误镜像回滚

记录当前镜像：

```bash
kubectl get deployment nginx-demo-nginx-demo -n demo \
  -o jsonpath='{.spec.template.spec.containers[0].image}'; echo
```

设置一个不存在的 tag：

```bash
helm upgrade nginx-demo deploy/helm/nginx-demo \
  --namespace demo \
  --set image.repository=ghcr.io/example/not-found \
  --set image.tag=does-not-exist
```

观察故障：

```bash
kubectl get pods -n demo
kubectl describe pod -n demo <异常Pod>
```

恢复上一版本：

```bash
helm history nginx-demo -n demo
helm rollback nginx-demo <正常版本revision> -n demo
kubectl rollout status deployment/nginx-demo-nginx-demo -n demo
```

## 三、NodePort 验证

```bash
kubectl get svc nginx-demo-nginx-demo -n demo
curl -I http://192.168.121.10:31258
curl -I http://192.168.121.11:31258
```

如果节点本地访问失败，依次检查 Endpoint、kube-proxy 和实际 nftables 后端，参考 `docs/incidents/nodeport-nftables.md`。
